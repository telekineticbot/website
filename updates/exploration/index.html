An exploration on exploration

Proposal for safe real world robot exploration.

Vineeth YeevaniVrishabh KenkreNovember 18, 2026

This animation needs WebGL. The steps below tell the same story.

We want robots that improve themselves.

Give it a task it can't solve yet.

It has to explore to find a way.

Most methods wiggle around and pray.1

Wiggling rarely finds anything new.

Ours: blindfold it and give it the rough plan.

It fills in realistic motion on its own.

Many new tries. One works.

A robot gets better at a task it fails only by trying something different. Online RL can then learn from the try that works.

So we need a dial that sets how far each try strays from what the robot would do, while every try stays a sensible move.

The obvious dial is Gaussian noise on the action. But a failing policy's error isn't random. It's a bias that depends on the scene: here it always closes the same distance left of the rim.

Small noise stays at the same miss. To reach a target of size a bias away, the chance falls exponentially with the action's dimension .

Noise big enough to cross the bias sends most tries into the table and the bowl.

The other dial is the policy's own spread: sample it again and hope for a different try. Whether that works depends on what flow matching learned, and robotics uses it very differently from image models.

An image model gets a short prompt, like "robot picking up a bowl". Many different pictures fit it. To lower its loss, the model has to learn all of them, so the variety lives in the model.

A policy gets the opposite: a camera image and joint angles in, a small action out. No two images are ever exactly the same. They're close, but each one comes with exactly one action.

Teleoperators are also taught to keep one consistent strategy, so nearby images get nearly the same action. Fitting one action per image is easy.

In information terms: every training state is unique, so on the data the state fixes the action.

Flow matching mixes noise into the action and trains a velocity to undo it.

With one action per state, the loss is lowest for a straight path to that action, from any noise.

So the policy has no variety to sample. On a new state it blends the actions of nearby states into one miss, the same one every time. This holds at the loss optimum, for a model expressive enough to reach it.

We saw it in our runs: drawing more samples didn't help on the hard cases, and DSRL,7 which steers the policy's input noise, improved tasks that already worked but struggled from 0%.

Now take the state away. Many different actions share one empty input, just like many pictures share one prompt.

A model trained on actions alone has nothing to lean on. Its best velocity points to the average of every action that could have made , so it has to learn the real spread of valid actions in data as broad as DROID.

This gives the dial. The blindfold takes the policy's plan, mixes in noise of strength , and lets pull it back to a valid action.

Small stays near the plan. Larger strays further, and every try is still a real grasp. Many new tries. One works.
